What agent:// is missing

The paper solves who. An identifier that answers who has nothing to say about where, and that is not a bug in it.

The paper solves who, and its identifier destroys where on purpose

The identifier is SHA-256 over the agent's capability set, so two agents whose sets differ by a single entry receive unrelated keys, and no threshold on those keys recovers a distance. That is correct for reference and for audit: an identifier that drifted with behaviour could not be used to name anything.

It is also why the scheme has nothing to say about location. Two agents doing nearly the same job have no distance between them at all, because strings have no metric. There is nothing to compare except equality.

The paper names this weakness in itself. Different organisations may describe equivalent capabilities with incompatible paths. Its own remedy is an external capability-mapping service: a second system to run, and a second source of truth that can drift from both sides it maps.

The five steps by hand

01 The two URIs, as issued

acme issues agent://acme.com/workflow/approval/01h0000000000000000000000 and globex issues agent://globex.io/process/authorize/01h0000000000000000000000. Both carry a stable unique suffix and a hierarchical capability path, and the path segments differ in both positions.

02 The two addresses, off the situations

acme's approval agent is ⌁ no.ki.ni.ke.ru·to.ru.ki.ru.ta+va.ki.ra.ma.no~ko.so.mo and globex's authorize agent is ⌁ no.ki.ni.ke.ru·to.no.ki.ru.ta+va.ki.ra.ma.no~ko.so.mo. Both are 18 syllables, and neither was derived from the capability path.

03 The Hamming distance between them

The two addresses agree on 17 of 18 syllables and differ at syllable 7, where acme reads ru and globex reads no. Two phonemes differ, which is the recorded Hamming 2, against 24.0 for non-equivalent pairs.

04 Discovery by capability path on this pair

Exact-path discovery finds nothing for workflow/approval, and across the four queries it scores recall 1/4. The single hit is process/audit, which prefix-matches all five process/* paths on the globex side, so it returns process/authorize, process/compile, process/revert, process/review and the decoy process/migrate. One of the five happens to carry the audit job, which is a shared string prefix and not a meaning.

05 Discovery by nearness on the same four queries

Nearest address returns the equivalent job every time: 2 for approval to authorize, 3 for build to compile, 2 for rollback to revert and 4 for audit to review, so recall is 4/4 with no mapping table in the path. The decoy is returned as nearest 0 times.

An agent inside a layered environment

Here is the harder case. An agent runs inside a declarative overlay environment: one config file names the environment, the two tools allowed in it, where each tool's config and cache really live on the host, and where the workspace comes from. Why any of this could work

Nothing so far explains why independently built systems agree. A shared vocabulary tells you what to answer with; it does not make two differently built systems put the same situation in the same part of their own space. If that were all that was happening, the addresses would be arbitrary but consistent, like two people agreeing to call a colour "seven".

The result implies something stronger. Situations appear to occupy a structure that independently trained systems have in common, and the primer is a chart laid over that structure rather than a substitute for it.

Hand two cartographers the same grid and they will label the same mountain the same way, and that agreement is only worth something because the mountain was there first. The grid is ours. The mountain is not.

the manifold is inferred from agreement · the chart is published and 3,300 bytes

Where it stops: the chart is shared too, but only when the states are unambiguous. Ambiguous states send the charts apart again, which is why the positions on this page are described in such plain, concrete English. This is the parent project's finding restated, and it is inferred from agreement rather than observed directly.

05 What that buys a registry

A registry holding only the root, the statement vocabulary and the commitment rule can recompute it from a published set and compare: 1 distinct output over 50 pinned runs, 1 over 50 unpinned runs, and 1 across fresh interpreters, which matched the in-process value. The primer is 3,300 bytes and the frame it derives is 67,561 bytes, 20.47 times the seed, and none of that frame is transmitted. Same bytes means the same situation was described, with no shared vocabulary, no mapping table and no third party.

Where the address has to stop

The address is descriptive and never authoritative. It must not absorb identity, trust, routing, or any of the paper's five requirements. agent:// is untouched, and the two objects ride alongside it and decide nothing on their own.

agent:// says who you are. ⌁ says whereabouts you are. The distance between two addresses says how close. The root says whether it is the same.

What is demonstrated here, and what is not

Demonstrated: an acme-to-globex query resolves to the equivalent job by nearness alone, with no mapping table anywhere in the path, at recall 4/4 against 1/4 for exact-path discovery. A root verifies without contacting the issuer, since 5 of 6 families produced the byte-identical root for locked_storeroom and any holder of the vocabulary can recompute it. The frame is usable by six independently-built model families. Precision is variable and measured: one axis names 3 of the 6 places, three axes name 4, four axes name 5, and six axes name all 6, at which point ⌁ ma.mo.ma already separates them. Identity and location are separated in code, and the commitment destroys adjacency on purpose.
Not demonstrated: that nearness resolves the capability-mapping weakness in a production federation. Two organisations with four hand-written situations is a demonstration, not a federation. The equivalent pairs were written as situations rather than observed from live traffic, and the four queries are run as a table rather than through a live discovery call. Both sides here derive their coordinates from the same primer, and a pair of organisations each holding its own frame is not measured.

The shared-vocabulary caveat is inherited, not discovered here. The parent experiment's handover report states it first: its blind cross-model matching used a shared anchor vocabulary and a deterministic encoder, so it demonstrates encoding-level matching given a shared primer. It does not establish independence from a shared ontology, and its recommended follow-up study has still not been run. This repository restates the caveat because it still applies and nothing here removes it.

The framing result underneath it is measured: across 90 family-and-place comparisons the same place came out nearest in 96.7% strictly and 100% counting exact ties, against a chance rate of 16.7%, and address Hamming tracks known distance at Spearman rho 0.9286 against a shuffled null of +0.0002 with a standard deviation of 0.2704. What this repository adds is a control the parent run did not have: a random-vocabulary null at equal information content scores 20.9% against the real 96.7%, so the content of the choices carries the signal rather than merely the size of the sets. If nearness needed a curated mapping to work, the four queries here would have needed one, and no mapping table is in the path.

Most of this is older than it looks

Geohash and proquints make short pronounceable identifiers; locality-sensitive hashing preserves neighbourhoods; Merkle commitments give exact, order-independent equality; metric embeddings and canonical correlation analysis map between spaces; RSA is decades old.

The narrow claim is the conjunction: pronounceable and Gray-coded and locality-preserving, plus independently built model families producing the same address and the same root. The novelty is in the join and in the measurement, not in any one part.
